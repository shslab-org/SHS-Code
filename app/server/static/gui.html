SHS Code GUI — Plain-Language Guide

SHS Code is an AI coding agent: you describe what you want in normal language, and it plans, writes and verifies code for you — while showing every step it takes. This guide explains the GUI in plain words. No programming knowledge needed. Full documentation lives at shs-code-docs.

🚀 Start here — your first task in 3 steps
1
Open the Agent panel (left menu). If the sidebar is hidden, click ☰ in the top bar or press Ctrl+B.
2
Type what you want in plain language, e.g. "create a Python script that renames all files in a folder to lowercase", then press Enter. Shift+Enter adds a new line instead of sending.
3
Watch the Activity column on the right — every file the agent reads or writes, every command it runs, appears there live. The final answer appears in the chat bubble. Nothing is reported "done" unless it actually ran and was verified.

That's it. Everything else in this GUI is for looking at what the agent did.

◧ What each panel does (one line each)
  • Dashboard — the overview page: model, GitHub identity, recent tasks & sessions.
  • Agent — where you talk to the AI and watch it work (chat + live activity).
  • Tasks — the history of jobs with their real status; click one to see its plan as a diagram.
  • Team103 — for very large goals: the work is split across many workers and checked by QA.
  • Workspace — two tabs. Files: browse your project and click a file to view it. Changes: a diff-viewer that shows exactly what changed — green lines were added, red lines were removed; pick Working tree / Staged / vs HEAD to compare different snapshots. The number on the tab shows how many files changed.
  • Terminal — run shell commands in the server's folder, from the browser.
  • Git — commit, branch, push, pull, see differences — with the agent properly credited.
  • GitHub — the agent's GitHub identity, plus creating/listing pull requests and issues.
  • QA — run the same verification the agent uses (build, tests, lint) yourself.
  • Sessions — past conversations; open one to read it or continue where you left off.
  • Logs — technical system messages (diagnostics; separate from your chat by design).
  • Memory — what the agent remembers about your project and about you.
  • Settings — which AI model/provider to use; keys are stored, never displayed.
  • Help / Guide — this page.
↔ Showing and hiding the left menu (navigation)
  • Click the ☰ button at the very left of the top bar to slide the menu in/out.
  • When the menu is hidden, a small ☰ MENU tab appears at the left edge — click it to bring the menu back.
  • Keyboard shortcut: Ctrl+B (Windows/Linux) or Cmd+B (Mac).
  • Your choice is remembered — the menu stays hidden (or visible) next time you open the GUI.
  • On a phone, the menu opens as an overlay; tap the darkened area or press Esc to close it.
💬 Understanding the Agent panel (chat vs activity)

Chat bubbles (left) are the conversation: your messages and the agent's final answers. Activity feed (right) is the agent's internal work log — files touched, tools used, steps counted. The activity feed is internal events, never mixed into your conversation.

  • Run Progress card: current status, step number, finish reason and tool-call count.
  • While the agent works, its answer streams in live, word by word.
  • ■ Cancel run stops a run — the session and everything done so far is kept.
  • A run ends with an honest finish reason (e.g. final_answer, max_steps). If something failed, you will see that it failed — the GUI never fakes success.
🏷 What the task statuses mean
  • pending — waiting; its dependencies aren't finished yet.
  • ready — all dependencies done, about to start.
  • running — being worked on right now.
  • partial — stopped midway (interrupted/timeout); can be recovered.
  • retryable — failed once, will be retried.
  • failed / blocked — failed / waiting on something that failed.
  • completed — ran and passed its checks. A failed task can never become completed.
⌨ Keyboard shortcuts
  • Ctrl+B / Cmd+B — hide or show the left navigation.
  • Enter — send the message you typed in the Agent panel.
  • Shift+Enter — new line inside the message box.
  • Esc — close the navigation overlay on small screens.
🔧 Troubleshooting (common questions)
  • "WebSocket disconnected" at the bottom-left — the connection dropped; the GUI retries automatically every 3 seconds. If it stays red, check that the server is still running.
  • "unauthorized — set ?api_key=" — the server started with an API key. Open the GUI as http://localhost:8000/gui?api_key=YOUR_KEY.
  • Nothing happens when I send a message — check Settings: a model and API key must be configured first.
  • Where is my conversation saved? — every session is stored on the server; find and resume it in the Sessions panel.
  • Is my API key visible anywhere? — no. Keys are stored with 0600 permissions and masked in every settings view.
🧭 How the GUI relates to the CLI

The GUI and the command line are two windows into the same running system — same Python runtime, same sessions, same tasks, same memory. Anything you start in the GUI is visible to the CLI and vice-versa. The GUI never guesses what the agent is doing: it is driven by structured events sent by the runtime, so what you see is what actually happened.
